# ARH-T-0004 · Preserve spawned Appium child handle on healthy existing endpoint

## Intent

Preserve ownership of a spawned Appium process across repeated `ios.appium.ensure` calls. The healthy existing-endpoint path can currently replace state with `child=None`, dropping the tokio child handle and making later shutdown unreliable.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Healthy existing-endpoint ensure preserves the stored child handle and pid when the base URL is the same spawned server. | Focused state/appium test. |
| A2 | Env-owned Appium endpoints still never receive a spawned child handle. | Focused env-source test. |
| A3 | `rzn.worker.shutdown` kills a spawned child after repeated ensure calls. | Unit/integration test with fake child or controlled process. |
| A4 | Persisted runtime metadata does not regress. | Existing state tests pass. |

## Non-goals

- Broader runtime state persistence cleanup; that is ARH-T-0012.
