# ARH-T-0008 · Preserve non-ASCII UI text during matching and extraction

## Intent

Preserve non-Latin UI labels in row/text/typeahead matching. `normalize_match_key` currently strips everything except ASCII alphanumerics, so CJK, Arabic, emoji, and similar labels can collapse to empty keys and get dropped or deduped incorrectly.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | Matching keys keep the existing ASCII-normalized form when nonempty. | Unit test covers Latin labels. |
| A2 | Matching keys fall back to whitespace-normalized Unicode when ASCII normalization would be empty. | Unit tests cover CJK, Arabic, emoji-only, and mixed labels. |
| A3 | Extract rows, extract text, and typeahead dedupe keep non-Latin rows instead of silently dropping them. | Extraction regression tests. |

## Non-goals

- Full locale-aware collation or transliteration.

## Verification

| Covers | Check | Result | Notes |
|---|---|---|---|
| A1,A2 | cargo test -p rzn_phone_worker --lib normalize_match_key | pass | Latin, CJK, Arabic, emoji-only, and mixed-label normalization coverage passed. |
| A3 | cargo test -p rzn_phone_worker --lib extract | pass | Extraction/typeahead non-ASCII dedupe regression coverage passed. |
| A1,A2,A3 | make release-check | pass | Integrated release gate passed after all wave-2 patches. |
