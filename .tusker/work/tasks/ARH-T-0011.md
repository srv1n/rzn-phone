# ARH-T-0011 · Add PR CI and harden release workflow permissions

## Intent

Add normal PR/push CI and reduce release workflow privilege. Release validation currently lives in the tag release flow, global workflow permissions are `contents: write`, and third-party actions are tag-pinned.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | PR and push CI runs the existing release-check equivalent without duplicating the command list. | Workflow lint/review plus local `make release-check`. |
| A2 | Release workflow grants `contents: write` only to the publish job and least privilege elsewhere. | YAML review or validation script. |
| A3 | Third-party actions are pinned to immutable SHAs, or a documented repo policy explains intentional tag use. | Workflow grep/check. |
| A4 | Existing Node 24 action-major work remains compatible with `phone-msi` rather than duplicated. | Review issue linkage. |

## Non-goals

- Publishing signed plugin ZIPs; that remains `phone-rc0` unless superseded separately.
